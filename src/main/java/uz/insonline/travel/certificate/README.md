# Сервис страховых сертификатов

Генерация PDF-сертификата INSON, хранение в MinIO и отправка пассажиру письмом (ТЗ п. 9.2–9.3).

Пакет самодостаточен и рассчитан на вынос в отдельный микросервис: единственная связь с модулем
выпуска — сообщение в RabbitMQ.

## Поток

```
POST /policy/issue ──► полисы выпущены ──► ответ а/к (не ждёт PDF, ТЗ п. 7.5)
                              │
                              └─► RabbitMQ: insurance.certificate.issue
                                        │
                                        ▼
                         CertificateListener → CertificateService
                                        │
                    ┌───────────────────┼────────────────────┐
                    ▼                   ▼                    ▼
            модель по данным     PDF (Thymeleaf +      MinIO: certificates/
            сообщения и           openhtmltopdf)        yyyy/MM/CERT-....pdf
            INS_CENTRUM_AIR_                                  │
            POLICY_REF                                        ▼
                                                     письмо пассажиру
                                                     с вложением
```

Ошибка обработки → ретраи Rabbit → очередь `insurance.certificate.queue.dlq`. Выпущенные полисы
при этом не затрагиваются: сертификат догоняется повторной обработкой сообщения.

## Контракт очереди

`CertificateRequest` (пакет `api`) — самодостаточное сообщение: бронь, язык, застрахованные лица
с e-mail, купленные продукты с количествами, программа авиа-пакета и выпущенные полисы с рисками
и страховыми суммами. Слушатель разбирает тело в `CertificateRequest` независимо от заголовка типа,
поэтому после переезда в отдельный сервис менять ничего не придётся.

## Откуда берётся содержание

| Что | Источник |
|-----|----------|
| Застрахованные, даты, номера полисов, количества мест багажа и питомцев | сообщение очереди |
| Страховые суммы по рискам | сообщение очереди (из справочника рисков на момент выпуска) |
| Объект страхования, формулировки рисков, территория, наименование продукта | `INS_CENTRUM_AIR_POLICY_REF` по `RISK_CODE` (ТЗ п. 6.1) |
| Покрытия с лимитами, сроки страхования, документы для выплаты, контакты ассистанса | `certificate-content.yml` |

`certificate-content.yml` меняется без релиза кода (ТЗ п. 11). Версия шаблона пишется в
`INS_INSURANCE_CERTIFICATE.TEMPLATE_VERSION` — документ воспроизводим.

## Идемпотентность

Сертификат один на бронь (`UQ_INS_CERTIFICATE_BOOKING`):

* повторная доставка сообщения по уже отправленному сертификату не делает ничего;
* `resend = true` переиспользует PDF из MinIO и только отправляет письмо заново;
* при падении после сохранения файла повтор не перегенерирует PDF, а берёт сохранённый.

## Настройка

```yaml
minio:
  endpoint: http://minio:9000
  access-key: ${MINIO_ACCESS_KEY}
  secret-key: ${MINIO_SECRET_KEY}
  bucket: insurance-certificates
```

Логотип: положить `src/main/resources/certificate/logo.png` — шаблон подставит его вместо
текстового логотипа. Шрифт документа — `resources/fonts/DejaVuSans*.ttf`, заменяется на
корпоративный правкой `CertificatePdfRenderer`.

Таблицы и последовательности — в `src/main/resources/db/centrum_air_idempotency.sql`.

## Что не сделано

* шаблоны UZ и EN: сейчас содержание сертификата настроено на русском, язык из сообщения
  прокидывается в шаблон, но переводы не заведены (ТЗ п. 9.2 требует двуязычный EN/UZ);
* `POST /policy/resend`: сервис умеет повторную отправку (`resend`), HTTP-метод не опубликован;
* электронный полис ЕАИС (PDF «в стол», ТЗ п. 9.1) — генерирует НАПП, здесь не формируется;
* письмо «Ваш страховой полис обновлён» при изменении полиса (ТЗ п. 9.3).
