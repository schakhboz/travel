# Модуль выпуска Centrum Air

Реализация ТЗ «Встроенное страхование пассажиров Centrum Air», v3.0.

## Эндпоинты

| Метод  | Путь                             | Назначение                                        |
|--------|----------------------------------|---------------------------------------------------|
| POST   | `/policy/issue`                  | Выпуск полисов по брони (идемпотентный)           |
| DELETE | `/policy/cancel`                 | Аннуляция полиса при возврате билета               |
| GET    | `/policies` (и `/policy/policies`) | Журнал полисов: период, продукт, статус          |

`/policy/policies` оставлен как алиас, чтобы не ломать текущую интеграцию; ТЗ требует `/policies`.

## Идемпотентность (ТЗ п. 7.3)

Ключ:
* заголовок `Idempotency-Key`, если он передан;
* иначе — `SHA-256(PNR | набор продуктов | paymentAttempt)`; `paymentAttempt` — новое необязательное
  поле запроса, по умолчанию `1`.

Поведение повтора:

| Состояние заявки | Что делает повтор |
|------------------|-------------------|
| `COMPLETED`      | возвращает сохранённый ответ первичного выпуска, ничего не выпуская |
| `PARTIAL` / `FAILED` | довыпускает только недостающие учётные группы |
| `IN_PROGRESS` (свежая) | `409 issue_in_progress` |
| `IN_PROGRESS` (старше `idempotency.in-progress-timeout`) | перехватывает зависший выпуск |
| тот же ключ, другое тело | `422 idempotency_key_reuse` |
| без заголовка, активная заявка на ту же бронь и продукты | `409 duplicate` (ТЗ п. 7.6.5) |

Каждая учётная группа выпускается в собственной транзакции (`PolicyGroupIssuer`), поэтому сбой на
третьем полисе не откатывает первые два, а факт выпуска сразу пишется в
`INS_CENTRUM_AIR_IDEMP_POLICY`.

Таблицы создаются скриптом `src/main/resources/db/centrum_air_idempotency.sql`
(`ddl-auto: validate` — DDL приложением не создаётся).

## Структура

```
config/      настройки модуля (продукт, курс, имена функций НАПП, пороги валидации)
domain/      ProductSelection, RiskCatalog, Kontragent — правила без БД и Spring
error/       коды ошибок ТЗ п. 7.6.6 и обработчик только для PolicyController
idempotency/ ключи, состояние заявки, довыпуск
jdbc/        весь прямой SQL и вызовы пакета ERSP_VOLUNTARY_INTEGRATIONS
service/     сценарии: валидация, расчёт, выпуск группы, оркестрация, журнал, аннуляция
```

## Сертификат и письмо пассажиру

После выпуска всех полисов брони модуль публикует заявку в очередь `insurance.certificate.issue`
и сразу отвечает авиакомпании. PDF-сертификат, его хранение в MinIO и письмо пассажиру —
в сервисе `uz.insonline.travel.certificate` (см. его README).

## Что осталось за рамками (ТЗ, но не реализовано)

* `PUT /policy/update` и `POST /policy/resend` — методы ТЗ п. 8.1;
* электронный полис ЕАИС (PDF, ТЗ п. 9.1) — формирует НАПП;
* ретраи при недоступности НАПП до 24 часов и статус «Ошибка выпуска» с алертом — ТЗ п. 7.4;
  сейчас неуспешная группа остаётся недовыпущенной до повторного запроса а/к;
* курс EUR берётся из конфигурации, а не из справочника курсов на дату выпуска — ТЗ п. 3.1;
* сверка премии с тарифной матрицей выключена (`validation.check-premium: false`) до согласования
  разбивки премии по рискам — ТЗ п. 13.
